# 中文历史故事：交付契约

**本文件取代此前的 C“虚构短故事”方案。资料卡是事实边界，不是题材种子。**

## 1. 交付目标

输入一张有来源的六字段史料卡，输出一篇 **150–200 字**的中文历史故事：

- 语言通顺，有完整叙事并自然收尾；
- 保留卡片要求的人物、时间、地点、事件和结果；
- 不增加资料中不存在的人物、数字或历史事件；
- 不改变事件顺序、因果关系和人物身份；
- 不以“虚构故事”免责声明代替事实准确性。

字数统一按去除标点与空白后的字符数计算。**每一篇都要落在范围内，不能只验中位数。**

## 2. 事实边界

系统保证的是“不偏离已审核的输入资料”，不是独立证明全部历史事实。发布前必须同时满足：

1. 资料来源和字段通过人工审核，条目的 `review.status` 为 `approved`；
2. 生成结果通过自动验收；
3. 人工逐篇对照资料复核生成结果。

自动检查可以发现缺名、错名、漏掉关键事实、额外数字等问题，但不能证明语义蕴含，也不能识别所有错误历史陈述。

## 3. 关键事实锚点

每张用于历史故事验收的资料卡必须声明：

```json
"acceptance": {
  "required_spans": [
    "1921年",
    "福建厦门",
    "创办厦门大学",
    "院系最齐全的五所大学之一"
  ]
}
```

`required_spans` 中的每一项必须逐字来自该卡六字段，`validate.py` 会拒绝无资料依据的锚点。人物字段声明的所有人名会自动加入必检项，不必重复填写。

第一版采用**保守的字面锚点**：允许漏掉一些合理的改写，但不把 n-gram 相似度冒充事实正确。后续若引入语义验收，必须另外用人工标注样本验证其误判率。

## 4. 自动验收

`research/kb/accept.py` 对每次生成逐篇检查：

| 检查 | 门槛 |
|---|---|
| stop | 模型自行输出 EOD，不能触顶截断 |
| chars | 每篇 150–200 字 |
| echo | 不得退化成“人物：……时间：……”资料复读 |
| person | 资料声明的人物全部出现，不得截断姓名 |
| facts | 所有 `required_spans` 全部保留 |
| entity | 未声明人物候选列入人工复核警告；无分词正则不作硬判 |
| number | 阿拉伯数字必须能在资料中找到 |
| repeat4 | 单篇 4-gram 重复率不得超过 5% |

缺少 `acceptance.required_spans` 时以 `FACT_SPEC` 失败，不允许静默退回旧的故事验收。

默认最多生成四个候选，遇到第一篇自动合格的故事即停止。报告同时给出：

- **first candidate**：首次生成通过率；自由模式下反映模型本身，约束模式下反映闭环首次候选；
- **automatic gate**：重试后的最终通过率，反映闭环输出能力。

不能用重试后的数字掩盖首次通过率。任何自动合格结果仍需人工史实验收。

```bash
uv run python -m research.kb.accept \
  --run runs/ple-zh-ground-s0-best.pt \
  --tokenizer data/zh-ground/vocab-16384/tokenizer.json \
  --attempts 4 --show --report runs/zh-history-baseline.json
```

全部条目自动通过时命令返回 0，否则返回 1。

## 5. 开发顺序

1. 主机端运行新验收，保留旧检查点作为失败基线；
2. 用事实骨架、候选生成、检查和重试搭成闭环；
3. 若未见资料卡仍无法保留关键事实，再实验显式 span-copy 机制；
4. 主机端通过新契约及人工复核后，才修改导出格式和 ESP32 运行时。

旧 C 方案中的 `ground-3M`、`mixfix-3M` 和 `b10` 都只是历史实验检查点。它们在新标准实测通过之前，不是出厂候选。
