# 中文短故事：交付契约

**本文件是 C 方案的落地文本。它取代 `docs/zh-material-spec.md` 里关于"输出必须复述材料"的部分；那份文件继续只规定语料格式。**

## 1. 承诺什么

设备收到一张题材卡，生成一个 **120–220 字**的中文短故事，并自己收尾。

## 2. 不承诺什么

**不复述卡片。**卡片里的人物、年份、经过、结果，都可能不出现在故事里，也可能改头换面出现。产品文案、README、演示文案里不得出现"根据资料生成""忠于史料""材料事实"这类表述。

## 3. 为什么

24 张真卡，同一套 prompt，三种干预，两个规模：

| 干预 | 实体覆盖 | 事件覆盖 |
|---|---:|---:|
| 3M，自由解码 | 0% | 0% |
| 3M，约束解码（强行塞名字） | 100% | 0–1% |
| 10M，自由解码 | 0% | 1% |
| 10M，约束解码 | 100% | 3% |

名字塞得进去，用不上；容量翻三倍，事件覆盖率只从 0% 走到 3%，而且那 3% 全部来自两张卡，自由组同值是蒙对的。同一批卡片上，模型会把材料里的"葛明"写成"鲁明"，却把这篇故事的经过逐句复现——**它背了故事，没读材料**。

这不是数据不够、参数量不够或词表的问题，两轮合成任务已经把这条排除掉了。继续承诺"复述"，就是在卖一个测出来是 0 的东西。

## 4. 卡片字段的约束力

六字段格式不变（语料就是这么造的，改格式等于重训），但它们在**产品语义**上分三档：

| 字段 | 约束力 | 实际表现 |
|---|---|---|
| 人物 | 弱提示 | 姓偶尔被借走，名字大多自造；出现截断名（"陈嘉"←"陈嘉庚"） |
| 时间 / 地点 | 中提示 | 会挑一个相近的场景（桥、码头、学堂），不一定用卡上的那个 |
| 起因 / 经过 / 结果 | 纯题材 | 不落地。它们的作用是让故事"有个方向"，不是让事实进故事 |

调用方不得因为故事没写卡片上的事件而判为失败。**判为失败的只有第 5 节的指标。**

## 5. 验收标准

脚本：`research/kb/accept.py`（24 张卡，`--tokens 200`）。

| 指标 | 门槛 | 含义 |
|---|---:|---|
| stop | ≥ 95% | 模型自己吐 EOD，不是被 token 上限截断 |
| median chars | 120–220 | 太短是碎片，太长是跑飞 |
| echo | 0 | 故事不得退化成复读卡片（"人物：……时间：……"） |
| hybrid | ≤ 4/24 | 允许偶尔出现"陈嘉"这种截断名，多了读者会当成真人 |
| median repeat4 | ≤ 5% | 4-gram 重复率，防死循环 |

`entity`（整串名字命中率）**不是门槛**，只作为诊断打印。它长期是 0%，把 0% 写进验收等于永远不发货。

`coverage.py` 以及 `constrain.py`（强制塞名字）保留为研究工具：前者量的是"没做到的承诺"，后者是"可选风格开关"——打开后名字保证出现，但代价是输出不再代表模型本身。

## 6. 当前出厂候选

| 检查点 | core | stop | median chars | hybrid | 备注 |
|---|---:|---:|---:|---:|---|
| `ple-zh-ground-s0` | 3.0M | 100% | 178 | 3/24 | **推荐**：单一主角、场景连贯 |
| `ple-zh-mixfix-s0` | 3.0M | 100% | 143 | 0/24 | 名字干净，但多人乱入 |
| `ple-zh-b10-s0` | 10.0M | 96% | 191 | 8/24 | 更顺，设备端 1–2 tok/s，不值 |

3M 在 4060 上 batch 16 训 2500 步约 4 分钟，设备端 10–20 tok/s。10M 多花一半显存换 13 个字和更多截断名，不划算。

## 7. 必须一起改的东西

- 设备端 UI：故事页标注"虚构故事，非史实"。第 2 节的产品风险是唯一无法用代码修的部分。
- `research/kb/README.md` 里"材料必须与语料逐字节同构"仍然成立（格式要求），但"模型把材料讲成故事"这句删掉。
- 演示脚本不要挑卡片去对故事内容，会立刻露馅。
