# 中文故事材料格式守则

本文件规定中文短故事语料的**材料—故事**成对格式。训练语料、生成提示、
语料检查脚本和部署时的外挂资料集都以此为准，四者必须逐字节同构。

**核心约定：模型不负责知道事实，只负责把给定材料讲成故事。**
因此材料的信息量必须大于故事的骨架，且材料里的每一条约束都必须是可判定的。

---

## 1. 一条样本

```
<|material|>
人物：李明，青石镇的木匠，四十岁上下。
时间：大晟三年深秋的一个傍晚。
地点：青石镇，镇口那座旧木桥。
起因：李明要把一张修好的长凳赶在天黑前送到桥对面的孙家。
经过：桥板早就朽了，他走到中间时桥板断了，长凳掉进河里。他脱了鞋下水，把长凳拖了上来。
结果：孙家留他吃了晚饭，长凳晾干后摆在门口，一直用到第二年春天。
<|story|>
李明把长凳扛在肩上出门时，日头已经斜到屋顶那么低了。他走得急，桥板在脚下一沉一沉，他也没停。走到桥中间，脚下咔的一声，一根木条断了，长凳从他肩上滑下去，扑通一声掉进河里，水花溅了他一裤腿。他站在桥上愣了一会儿，把鞋脱了，卷起裤腿，慢慢下到水里。水凉得他直吸气。他摸到长凳的腿，一把抓住，往岸上拖。等他把长凳拖上来，天已经擦黑了。孙家的人在门口等他，看见他一身水，赶紧把他拉进屋，端来一碗热饭。第二天，长凳晾在院子里，晒了两天，孙家把它摆在门口，一直摆到第二年开春。
<|endoftext|>
```

一条样本 = 一份材料 + 一个故事 + 一个结束标记。没有其他内容，没有注释，
没有空行。

---

## 2. 字段规范

六个字段，**顺序固定，缺一不可，各出现一次**。全角冒号，冒号后不空格。

| 字段 | 内容 | 字数上限 | 必须包含 |
|---|---|---:|---|
| `人物` | 全部出场人物：姓名 + 身份 + 一个可叙事的特征 | 40 | 每个人物的姓名 |
| `时间` | 时代 + 季节/时辰 | 20 | 一个时间锚点 |
| `地点` | 一个主场景，可选一个次场景 | 20 | 具体到镇/村/店/桥 |
| `起因` | 一句话，一个具体的动作或需求 | 60 | 一个可观察的动机 |
| `经过` | 2–3 句，按时间顺序的外部事件 | 100 | 至少一个转折 |
| `结果` | 一句话收束 | 50 | 结局状态 |

材料合计 **≤300 字**，故事 **≤360 字**。

### 2.1 人物

- 1–3 人，姓名 2–4 个汉字，用常见姓氏。
- 每个人物必须带身份（木匠、货郎、教书先生），或带一个可在故事里复用的特征（左腿有点跛、总戴一顶旧草帽）。
- **姓名必须随机生成**，语料中永远不得出现"小明""小红""张三""李四"这类默认名，理由见 §5。

### 2.2 时间

- 允许虚构年号（大晟三年、昭和…）、节气、农历日期、时辰。
- 表达分布必须够宽：`大晟三年深秋`、`腊月二十三`、`天没亮`、`晌午刚过`、`入伏第三天`。
- 只写一个锚点，不写时间跨度。跨度交给故事层。

### 2.3 地点

- 具体到可指认的场所：`青石镇`、`镇口那座旧木桥`、`城南的当铺`、`西山脚下的窑`。
- 不得使用"一个地方""某处"这种无约束表述。

### 2.4 起因 / 经过 / 结果

- 只写**外部可验证的事件**：谁做了什么、发生了什么、最后怎样。
- 不写心理活动、回忆、比喻、抒情。这些属于故事层，写进材料会让模型把叙述与事实混为一谈。
- `经过` 必须有至少一个转折（桥板断了、货丢了、人没来），否则故事没有可讲的东西。

---

## 3. 存盘格式

语料文件 `seeds/zh/pairs.txt`，UTF-8，无 BOM，换行统一 LF。

- 文档之间以 `<|endoftext|>` 分隔，标记独占一行。
- 每条内部 `<|material|>` 与 `<|story|>` 各出现一次，顺序固定。
- 三个标记注册为**特殊 token**：BPE 训练前从文本中剥离，训练完成后
  `add_special_tokens` 加回，保证各占 1 个 token。

---

## 4. token 预算

| 部分 | 字数 | token（按 1.7 字/token） |
|---|---:|---:|
| 六个字段标签 | — | ≈30 |
| 材料正文 | ≤300 | ≤176 |
| 故事 | ≤360 | ≤212 |
| 三个标记 | — | 3 |
| **合计** | | **≈420** |

训练 `seq_len=512`，部署同样 512。超出 512 的样本一律丢弃，不得截断——
截断的故事会教模型在句子中间停下。

## 5. 强制校验

以下每条都是可以在 `check_corpus.py` 里实现并返回布尔值的。任一条不过，
整条样本丢弃并记录原因。

- **M1 结构**：六个字段按序齐全，各出现一次；材料块先于故事块。
- **M2 长度**：材料 ≤300 字，故事 ≤360 字，故事 ≥120 字。
- **M3 实体闭合（双向）**：
  - 故事中出现的全部专名，必须在材料的 `人物` 或 `地点` 中出现过。
  - 材料 `人物` 中的每个人，必须在故事中出现至少一次。
  - 专名候选的判定：以常见姓氏开头、长度 2–4 的汉字串；或以
    `镇/村/店/桥/山/河/寺/馆/铺/巷/街/庄/坊` 结尾、长度 2–5 的汉字串。
- **M4 数字一致**：故事中出现的年份、数量，必须在 `时间` 或 `经过` 中出现过。
- **M5 字符集**：不得含拉丁字母、数字阿拉伯写法混排、U+FFFD。
- **M6 引号**：引号成对，不跨段。
- **M7 近重复**：与既有样本的字符 4-gram Jaccard < 0.60。
- **M8 名称黑名单**：不含 `小明/小红/张三/李四/王五/某某`。
- **M9 批次级分布**：单一批次内，任一 5 字短语的文档覆盖率 < 20%；时间表达
  至少落在 5 种不同型式上。

```python
# M3 的可执行骨架
NAME = re.compile(r"(?:[赵钱孙李周吴郑王冯陈褚卫蒋沈韩杨朱秦尤许何吕施张孔曹严华金魏陶姜]"
                  r"[\u4e00-\u9fa5]{1,3})")
PLACE = re.compile(r"[\u4e00-\u9fa5]{1,4}(?:镇|村|店|桥|山|河|寺|馆|铺|巷|街|庄|坊)")

given = set(NAME.findall(material)) | set(PLACE.findall(material))
used  = set(NAME.findall(story))    | set(PLACE.findall(story))
assert used <= given, f"story invents entities: {sorted(used - given)}"
for person in NAME.findall(field("人物")):
    assert person in story, f"person {person} never appears"
```

M3 是整个设计的支点：它把"写错主人公"从概率问题变成一个可判定的布尔值。
部署时同一套判定做成运行时校验器，不通过就重新采样。

## 6. 故事层允许与不允许

| 可以自由发挥 | 必须服从材料 |
|---|---|
| 对白、心理、感官细节、天气、动作节奏 | 人物身份与人数 |
| 材料未提及的次要物件（一条狗、一盏灯） | 地点与场景关系 |
| 具体的比喻和句式 | 时间锚点与先后顺序 |
| 结尾的语气（暖、平、冷） | 起因、转折、结果三件事 |

原则：**材料规定"发生了什么"，故事负责"怎么发生的"。**
次要物件可以加，但不得成为事件的一部分；一旦它推动了情节，就必须先进材料。

---

## 7. 采样维度（防塌缩）

生成材料与故事时，以下四个轴必须拉开，且单一批次内任一取值占比 <35%：

- **主角年龄**：儿童 / 青年 / 中年 / 老人
- **主角处境**：手艺、赶路、看管、寻找、等待、失而复得
- **转折性质**：失误 / 意外 / 误会 / 天气 / 他者的介入
- **结尾语气**：回归 / 未解 / 平淡 / 反讽

禁止"小动物在森林里遇到危险又化险为夷"这一单一模板占主导——这是上一批
语料塌缩的原因。

---

## 8. 部署时的条目格式

外挂资料集里的每条，**就是 §1 中 `<|material|>` 到 `<|story|>` 之间的
文本**，一字不改，含换行与全角冒号。标题与编号作为元数据单独存放，不喂给
模型。

设备端二进制布局：

```
[index]  N × { u16 id, u16 title_off, u16 mat_off, u16 mat_len }   # 定长
[blob]   标题 + 材料正文，UTF-8
```

固件按键选题后按偏移直取材料、拼进 prompt，不做任何解析。

## 9. 交付检查单

一份语料提交前，逐项打勾：

- [ ] M1–M9 全部通过，`check_corpus.py` 零报错
- [ ] 人工抽查 50 条，确认每条材料**足以唯一支撑**其故事
- [ ] 时间表达 ≥5 种型式，人物姓名无重复度过高者
- [ ] 材料平均信息量：每个字段都非空且非模糊表述
- [ ] 训练集与验证集按文档切分，验证集占比 ≥1%，且不少于 200 条
- [ ] 10% 的样本以"仅材料、无故事"形式生成，用于训练模型在无目标时也能开口
